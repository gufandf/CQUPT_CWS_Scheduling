# 勤工助学中心学生打印社排班工具

为解决学校勤工助学中心学生打印社的部门排班问题所制作的排班工具：
**输入学号 → 自动抓取教务课表 → 按空课时间排出单双周值班表 → 导出值班表 / 空课表 Excel。**

## 快速开始

1. 安装依赖：`pip install -r requirements.txt`
   （也可以只装 `pip install requests urllib3`——程序实际只用到这两个库，详见「注意事项」）
2. 启动服务：Windows 双击 `start.bat`，其它平台运行 `python3 app.py`
3. 浏览器打开 `http://localhost:8765` 进入工具
4. 点顶部**「文件」菜单 → 导入学号…**，在弹窗里粘贴 10 位学号（每行一个）后点「导入」，
   课表会自动从教务系统抓取；课表就绪后点左下角的**「开始排班」**自动分配值班。

> 学号录入框在**弹窗**里，不再常驻左侧面板；随时可以再次从「文件」菜单打开它追加学号
> （已有的排班不会被清空）。

> ⚠️ **两件最容易踩的事**：
> 1. 抓课表需要**校园网或 VPN**，并且必须**通过 `app.py` 打开**（不能直接双击 `index.html`）；
> 2. **排班数据只存在内存里，刷新页面就没了**——排完班请立刻用「文件」菜单 →「导出数据」
>    保存 JSON，下次用「导入数据」恢复。详见下方「注意事项」。

## 功能

1. 输入学号自动从教务系统获取当前学期课表（需要连接校园网或使用 VPN）
2. 设置忽略课程（自动识别“实训”“实践”等关键字进行忽略）
3. **右侧表格始终显示**：打开页面即可看到当前值班模板的所有时段与人数（未排班时显示 `0/2` 这样的空位），
   不必先点「开始排班」——也可以直接把左侧同学拖进格子手动排班；未导入学号 / 未获取课表 / 未排班时，
   表格上方会有一行提示说明当前状态
4. **两种视图**：右上角可在**「值班表」**（谁在值班）与**「空课表」**（每个时段谁有空）之间切换，
   单周 / 双周也在这里切换
5. **一个「开始排班」按钮 + 左侧「限制每人每周班次」开关**（自动排班始终遵守课表冲突与班次人数上限）：
   - **不勾选开关**（默认）：不限制每人的班次数，谁空谁上；
   - **勾选开关**：强制遵守右侧填写的「每人每周最多班次」（单周、双周各自单独计数）；
   - **无论是否勾选，都会尽量让每人的班次数相近**（不勾选时同样做均衡优化）。
6. **连续排班开关**（见下方「连续 / 分散排班」）：勾选后尽量把同一人的班次连成片，不勾选则尽量分散
7. 鼠标拖动进行排班，拖动时显示空闲班次；**锁图标**可把调好的时段锁住，重新排班不会改变它
8. **值班时间模板**：可自定义每个班次的值班时间、值班人数、单双周，自由增删班次
9. 导出导入 json 文件（含值班模板）
10. 导出值班表和空课表（值班表额外附带一张**人员表**，见下方说明）

## 排班锁定

已经手动调好的时段怕被下一次自动排班冲掉？点学生标签上的**锁图标**即可锁定：

- 锁住的是**「该同学 + 该班次」这个位置**——锁定后，无论怎么点「开始排班」重新分配，
  这个位置都**不会再被改动**（不换人、也不换时段）。
- 锁定**不会**把人「钉死」：这位同学在**其它**班次仍可被正常安排，其他同学也照样能排进这个班次。
- 已锁定的标签会变成**琥珀色**并显示闭合的锁图标，且**不能拖动**、**不能点 × 移除**
  （会提示先解锁）；再次点击锁图标即可解锁。
- 锁定状态**只在内存中**（本工具不使用浏览器存储），但会**随「导出数据 / 导入数据」一起往返**；
  点顶部**「文件」菜单 → 重置排班…**（确认后）会连同锁定一起清空。

## 每人每周最多班次（左侧开关）

左侧「学号列表」下方的**「限制每人每周班次」开关**决定要不要套用每人每周的班次上限，
勾选后才轮到右边的数字框生效（未勾选时数字框变灰不可改）：

| 开关 | 数字框 | 行为 |
| --- | --- | --- |
| **不勾选**（默认） | 不生效（灰显） | 不限制每人班次，谁空谁上 |
| **勾选** | 生效 | 每人每周最多排这么多班（可填 `1` ~ `99`） |

- **单周、双周各自单独计数**：上限是「每周」的口径，不是两周合计。
- **无论是否勾选，程序都会尽量让每人的班次数相近**——不勾选时同样会做均衡优化，
  只是不以「不超上限」为硬约束。
- 数字框里的 `0`、负数或非法值一律**回落为默认值 3**；开关与数值**只在本次会话内有效**（刷新后回到默认）。
- 名额不够时（人数 × 上限 < 班次总需求），部分班次会空着，程序会提示有多少个班次没排满，
  **不会为了填满而偷偷超限**；名额会尽量摊到整周，不会只堆在周一至周五。

## 连续 / 分散排班

左侧的**「连续排班」开关**决定同一名同学的班次怎么摆放：

| 开关 | 效果 |
| --- | --- |
| **勾选** | 尽量把班次**连成片**：同一天内首尾相接的班次要尽量给同一个人（连班，少跑几趟），相邻的几天也尽量连着排同一个人 |
| **不勾选**（默认） | 反过来尽量**分散**：避免同一天连班，也避免连着几天都排同一个人，把班次摊到整周 |

- 判定口径：同一天内**首尾相接**（前一班结束到后一班开始空档不超过 30 分钟）算一次「连班」，
  **相邻两天都值班**也算一次连续。
- 这是「**尽量**」的软偏好：算法只做**不改变任何人的班次数**的等价换人，因此
  **不会破坏「尽量让每人班次数相近」这条均衡性**，也不会绕过课程冲突、班次人数与锁定。
  一个班次人数满了、或换过去会撞课，就不会换。
- 一周只排 1 个班的同学，无论排哪天都谈不上「连不连续」，因此不会被这项偏好搬动。
- 开关状态**只在本次会话内有效**（刷新后回到默认的「分散」）；点「开始排班」时就会按它执行。

## 值班时间模板

点顶部**「文件」菜单 → 编辑值班模板…** 打开编辑器（模板文件的**导入 / 导出**也在同一个「文件」菜单里）。
模板按**排班日分组**组织，每组各自独立维护班次列表，
因此不同分组的班次数量、时间、人数都可以完全不同。

### 排班日分组

支持两种模式，随时可在编辑器顶部切换，**切换时班次与已有排班都会保留**：

| 模式 | 说明 |
| --- | --- |
| **工作日 / 周末**（预设） | 固定两组：周一至周五一套班次、周六至周日一套班次 |
| **一周 7 天自由组合** | 分组数量（最多 7 个）、名称与每组包含的星期都可自定义 |

自由组合模式的用法：

- 每个分组可单独勾选包含哪些星期，**同一天只能属于一个分组**
- 常见组合：周一周二一组 / 周三到周五一组 / 周末一组；也可以「每天独立」（7 组各一套班次）
- 快捷按钮：**每天独立** 一键拆成 7 组；**合并为工作日/周末** 一键并回两组
- 未被任何分组选中的星期**当天不排班**，编辑器会给出提示（不阻止保存）
- 编辑器顶部有「星期归属」一览，一眼看清 7 天分别归哪个分组

每个班次可设置：

| 设置项 | 说明 |
| --- | --- |
| 值班时间 | 班次的开始与结束时间，如 `10:00` - `12:05` |
| 值班人数 | 该班次需要的人数上限，自动排班按此人数分配 |
| 单双周 | 「每周」每周都排；「仅单周」/「仅双周」只在对应周次生效 |
| 冲突课程节次 | 与该值班时段冲突、不可排班的课程节次 |
| 启用/停用 | 临时停用某个班次而不删除它 |

> **允许整个分组只排单周或只排双周**，例如「工作日组只排单周、周末组每周都排」。
> 此时该分组在另一周不排班，分组头上会显示「仅单周 / 仅双周」徽标；保存**不会被拦截**，
> 只给出一条提示说明哪一周不排班。导出时仍会生成单周、双周两个工作表，
> 该周没有班次的分组保留分组行并标注「（本周无班次）」。

其它能力：

- **自由增删班次**：可添加、复制、删除班次，并用 ↑↓ 调整顺序（保存时按开始时间自动排序）
- **冲突节次自动推导**：默认按值班时间与每节课时间的重叠关系自动计算冲突节次，
  也可手动点击节次覆盖，并随时「恢复自动」
- **模板不自动保存**：本工具不使用浏览器存储，刷新或关闭页面就会回到**内置默认模板**；
  改完请立刻用「文件」菜单 →「导出值班模板…」存成文件
- **模板导入导出**：可把模板导出为独立 JSON 文件分享，或从文件导入
- **恢复默认**：一键回到系统内置的默认值班时段
- **防误触**：编辑器窗口**不会**因为点到窗口外的灰色遮罩而关闭（改动先写在草稿里，
  误点一下整窗消失就白改了）。关闭入口只有：右上角 **×**、底部**「取消」**、以及 **Esc**；
  三者都会丢弃草稿，想保留改动请点**「保存并应用」**。

> 修改模板后，被删除班次的原有排班会在保存时自动清除，其余班次的排班完整保留。
> 把某天挪到别的分组、或改动分组结构时，**只要班次和它所在的天没变，排班就不会丢**。

## 人员表（导出值班表时附带）

点「导出值班表」得到的 Excel 里，除了「单周值班表」「双周值班表」，
还有第三个工作表**「人员表」**——把「按班次看人」翻转成「按人看班次」，
值班的同学可以直接在里面查自己什么时候有几班：

| 段 | 内容 |
| --- | --- |
| 概览 | **姓名 / 学号 / 单周班次 / 双周班次 / 合计**，每人一行，班多的排前面 |
| 明细 | **姓名 / 学号 / 周别 / 星期 / 班次名称 / 时间段 / 分组**，逐条列出每个人每个班 |

> 统计口径：**合计 = 单周班次 + 双周班次**。单周与双周是**各自独立排班**的：
> 「每周」的班次在单周、双周各有一个独立槽位，两边各自计数，
> 因此同一人若单双周都被排上，就会各计 1 次（合计 2）。
> 「周别」列写的就是**班次自身的周期**（每周 / 仅单周 / 仅双周），不是它被排进的那一周。
> 没有排到班的同学也会保留一行并显示 0，不会出现「在表里找不到自己」的情况。
> 「导出空课表」**不含**人员表（空课表是「谁有空」的清单，没有班次归属）。

### 默认模板

| 分组 | 班次 |
| --- | --- |
| 周一至周五 | 早班 10:00-12:05 (2人)、午班① 12:05-13:45 (3人)、午班② 13:45-15:50 (2人)、下午班 15:50-18:00 (2人)、晚班① 18:00-19:45 (2人)、晚班② 19:45-21:35 (1人) |
| 周六至周日 | 早班 10:00-12:00 (2人)、午班① 12:00-14:00 (2人)、午班② 14:00-16:00 (2人)、下午班 16:00-18:00 (1人) |

## 数据格式（JSON）

「导出数据」产出的 JSON 是**整套存档**，包含课表、排班与**值班模板**（数据格式 `version: 3`），
可在工具内导入导出；导出的模板可直接复用为下一学期的基础配置。
关键字段：

| 字段 | 内容 |
| --- | --- |
| `template` | 完整的值班模板（分组、班次、时间、人数、单双周） |
| `students` | 学号、姓名、原始课表与忽略课程（导入后无需重新联网抓取） |
| `assignments` | 单周 / 双周各自的排班（键为 `{周别}_d{星期}_{班次id}`） |
| `locks` | 已锁定的排班位置（`version 3` 起；旧文件没有此字段＝全部未锁定） |

> **兼容性**：`version: 2` 及更早的旧文件仍可导入——没有 `template` 字段时沿用当前模板，
> 没有 `locks` 字段时按「全部未锁定」处理。

## 注意事项

1. **本工具不在浏览器里保存任何数据，刷新页面一切归零。** 学号、课表、排班、锁定、模板、
   主题与各开关都只存在内存中（不使用 localStorage / cookie 等任何浏览器存储）。
   **排完班请立刻用「文件」菜单 →「导出数据」保存 JSON**，下次打开用「导入数据」恢复；
   模板另可用「导出值班模板…」单独留存。
2. **抓课表需要校园网或 VPN。** 课表来自红岩网校 API（主）与教务在线（备），
   两者都失败时后端返回 502，该同学会被标记为 `error`，可用左侧「刷新课表」或课表弹窗里的「刷新」重试。
3. **必须通过 `python3 app.py` 使用，不能直接双击 `index.html`。**
   抓课表由本地 Python 后端代发请求（浏览器直接请求会跨域失败）。
4. **导出 Excel 依赖一个 CDN。** 页面从 cdnjs 加载 `xlsx.full.min.js`（项目唯一的外部前端依赖），
   **完全离线时导出功能会失效**；如需离线使用，可把该文件下载到 `templates/` 下改为本地引用。
5. **`requirements.txt` 是一份完整的 `pip freeze`，但程序实际只用到 `requests` 和 `urllib3`。**
   其余列表项是历史遗留，重新部署时 `pip install requests urllib3` 即可运行，不必照单全装。
6. **不要用浏览器直接打开导出的 JSON 改着玩**——它是「导入数据」的输入，
   手工改坏结构可能导致排班被清理。

## 开发与自测

改动前端逻辑后，可运行不依赖浏览器的自测套件（只需 Node）：

```bash
bash .selftest/run-all.sh      # 全部通过时末行输出「结果：171 通过 / 0 失败」
```

自测会直接从 `templates/index.html` 抽取内联脚本执行，**测的永远是最新代码**，无需构建。
面向 AI 编码代理的架构约束、性能要求与已知陷阱见 **[AGENT.md](AGENT.md)**。
